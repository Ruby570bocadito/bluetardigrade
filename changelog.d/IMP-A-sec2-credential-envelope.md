- The Active Directory connector credential now lives in a SEC-2 envelope: `engine secret-write <file> < pw.txt` wraps one secret per file in a versioned JSON document — DPAPI-encrypted (LOCAL_MACHINE scope) on Windows, atomically installed with owner-only `0600` elsewhere — and `password_file` in the `-ad` config reads it transparently.
- Legacy raw-text credential files keep working, but on Windows the connector now surfaces a one-line warning on `/api/ad/status` pointing at `engine secret-write` until the file is re-saved encrypted; nothing is rewritten behind the operator's back.
- A plain envelope with group/other permission bits is refused with an actionable `chmod 600` hint instead of being read; a corrupted envelope is a hard error instead of being silently swallowed as a password.
- The AD service-account secret is zeroed from memory right after every bind attempt, and failed binds report server and result code only; tests now assert that no `/api/ad/*` response ever contains the secret, its base64 or hex form, or its length.
