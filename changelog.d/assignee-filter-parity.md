- **One unassigned queue, one assignee filter, everywhere.** After PR #45 (M-1) landed `assignee=none` on the alert search and export while the list kept `unassigned=true`, the two implementations disagreed on the same query parameter: `none` was a literal operator name on the list but the unassigned queue on search/export, and `unassigned=true` was silently ignored outside the list (a queue view built on search or export silently returned everything). One shared parser (`parseRecordFilter`) and one matcher (`assigneeFilterMatches`) now serve the list, the search and the alerts export: `unassigned=true` and `assignee=none` mean the same queue on every endpoint, invalid values are loud 400s everywhere, and the contradictory `assignee=<name>&unassigned=true` stays a 400 while the redundant `assignee=none&unassigned=true` is allowed. OpenAPI documents the filters on search and export and the reserved `none` value.
