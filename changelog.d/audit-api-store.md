- **A notification channel can no longer be pointed at another host with its stored secret, nor read the engine's environment.** `PUT /api/settings/notify` kept the stored token or password when the `url`, `api_url` or `server` of a channel changed, and resolved any `token_env`/`username_env`/`password_env` name against the engine process: with `-api-write`, a channel aimed at a foreign server with `token_env: SF_API_TOKEN` and one "send test" delivered the secret. A changed destination now requires the secret again, and the API only accepts environment names starting with `SF_NOTIFY_` (a name the file already had is kept while channel and destination stay the same; the YAML file itself is not restricted).
- **The sign-in throttles block before checking, and domain sign-in is also throttled per account.** Both throttles were consulted after the token comparison or the LDAP bind and only on failure: a blocked address kept sending guesses to the domain controller, and a correct credential still answered 200. Past the budget every request now answers 429 until the window ends, whatever the credential, and nothing reaches the directory. Domain sign-in counts failures per target account as well as per address (the address is the console's for every user).
- **A slow or silent domain controller no longer holds the engine's startup.** The first Active Directory sync ran before the API and the detection pipeline started, with no deadline on the TLS handshake (none at all on the StartTLS path): a server that accepted the connection and said nothing left the engine without detection for good. The first sync now runs in the background, connection and handshake share a 15-second deadline, and `timeout_ms` of the domain sign-in covers the bind and the search, not only the handshake.
- **Retention and ordering no longer trust the sender's clock.** Events and alerts were pruned and sorted by the timestamp the sensor declared: one dated 2100 was never pruned and stayed on top of every listing, a backdated one was deleted within five minutes, and a year outside 1678-2262 overflowed. Rows now carry `received_at` (existing databases are migrated on open) and retention runs on it; a timestamp ahead of the engine clock sorts as "arrived now" while the stored evidence keeps the declared value; events dated before 1970 or from 2200 on are refused at ingest with a clear error. Imported old logs are therefore kept for the whole retention window, counted from the import.
- **The Active Directory service account password is not sent to a server the request names.** `POST /api/ad/test` and `PUT /api/settings/ad` accepted a new `server`, `port` or `bind_dn` and used the stored credential against it. A request that changes any of the three must now carry `password`.
- **The read-only SQL surface bounds memory, not only rows.** `SELECT hex(zeroblob(900000000))` is one row. A single value above 16 MiB is now refused by SQLite before it is built, and a result is cut at 32 MiB with `truncated: true`.
- **Overlapping saves of the Active Directory settings no longer undo each other.** Each `PUT` merged its fields into the configuration it had read before waiting for the write lock, so the second of two overlapping saves silently reverted the first.
- **The triage file survives a power loss, and a bulk assignment writes it once.** The alert lifecycle file was renamed into place without being flushed, so a power cut could leave it empty and the engine refuses to start on a triage file it cannot read. It is flushed first. Assigning a selection of alerts rewrote the whole file once per alert (up to 500 times, holding the lock); it is now a single write.
- **Large Active Directory groups sync with their members.** A group above the server's value-range limit (1500 members by default) is returned as `member;range=0-1499`, which the connector read as an empty group: no membership edges, and the posture findings that depend on them saw nobody. Every range is now followed.
- **Baseline and inventory are saved on shutdown and retried after a failed write.** Up to 30 seconds of learned baseline and fleet inventory were lost at every stop, a failed write lost what had been learned for good, and a failing retention pass was silent. There is a final save when the engine stops, unsaved entries are kept for the next attempt, and a prune error is logged.
- **Accounts limited to host groups no longer reach the scenario battery or the active-response internals.** `/api/scenarios*` now answers 403 to them like the other platform surfaces, and `/api/respond/state` tells them only that the surface is armed (no file paths, operator or protected-process counts, or audit size).
- **Server-side failures no longer return local paths.** The respond audit, the host-groups editor and the scenario routes answered a 500 with the raw error, file paths of the engine host included. The body is now fixed and the detail goes to the engine log.
