- **The AI analyst answers when its view is opened directly.** Loading the console on `?view=analista` (or reloading there) left the panel listening to nothing: it subscribed before the socket existed and never again, so an analysis showed "analysing" for good. The panel now subscribes when the channel comes up, and an alert handed over from the queue waits for it instead of being dropped.
- **A follow-up question and "Retry" address the alert that was analysed.** The question went to the newest alert in the queue, and "Retry" to the first alert with the same rule name, possibly on another host. Both now use the alert of the conversation, which stays highlighted in the list, even after it has left the live queue.
- **Analyses no longer mix, and a lost connection ends them.** Every analyst request carries an id that the hub echoes on each frame; the panel ignores frames of any other request. When the socket drops, the panel stops waiting and says so, and the hub cancels that console's analyses and their provider calls instead of holding its two slots for up to two minutes.
- **The analyst hub no longer sends telemetry to sockets.** Every connection received a snapshot and the live broadcast of all machines' events, alerts and stats, which the console stopped using long ago. An account limited to host groups was kept away only by not being given the hub token, which does nothing on a hub that runs without one. The hub now keeps that copy for the analyst alone; `console:snapshot`, `console:event`, `console:alert`, `console:alert_lifecycle`, `console:stats`, `console:suppressions` and `console:sequences` are gone.
- **With `HUB_ACCESS_TOKEN`, the hub's status needs the token.** `/` and `/health` told anyone on the network the engine endpoint, the provider URL and model, the allowed origins, the first rules and the counters. They now require `Authorization: Bearer <token>`; without it `/health` answers `{service, status}` and `/` answers 401. A hub without a token (loopback) is unchanged.
- **Another site cannot make the console query the engine.** The engine proxy checked for a cross-site browser context only on writes. On the default console (loopback, no credentials) a page elsewhere could fire reads with a cost, such as a reputation lookup that spends VirusTotal or AbuseIPDB quota. Cross-site reads are refused; the console's own requests, a typed address and clients without browser headers are not affected.
- **Administration reads need an administrator.** A viewer or an analyst could read the notification and Active Directory settings, the enrollment tokens and pending machines, the active-response audit and `/metrics`, whose writes are an administrator's. Those reads now answer 403 to the other roles; the Respuesta activa view says the audit is an administrator's read, and the Hosts view shows no enrollment state.
- **The analyst reconnects for as long as the tab is open.** The client gave up after ten attempts, so a hub started a minute after the console stayed offline until a reload.
- **The hub's copy of alerts is not duplicated or stale after an engine restart.** Each reconnection replayed up to 160 events and 48 alerts on top of the ones already held, and nothing was dropped when the engine went away, so the analyst could answer from a copy the restarted engine no longer had. The copy is cleared when the engine goes down and before each replay, and a record already held is not stored twice.
- **A frozen engine no longer looks connected to the hub.** The hub waited on the engine's event stream with no deadline; a half-open connection kept `/health` on "connected". The stream is dropped and reopened after 45 seconds without a byte (the engine sends a heartbeat every 15). Stats are polled one request at a time, so a slow engine cannot stack them or let an old answer overwrite a newer one.
- **Refused analyst requests do not spend the minute's budget.** A click while two analyses were running, or with the analyst not configured, used one of the ten requests per minute. Slots and configuration are checked first, and the budget follows a monotonic clock rather than the wall clock.
- **Links and images in the analyst's answer are not rendered.** The answer is model output over telemetry an attacker can write; a crafted command line could make it show a clickable link or load an image from anywhere. Their text is kept, the element is not.
- **The sign-in lockout counts once, and the shared token has an attempt limit.** The failure counters lived in a module that the console loads twice (request proxy and routes), so each copy could keep its own count. They are shared now. A console gated by `CONSOLE_ACCESS_TOKEN` alone had no limit at all on wrong tokens: they are limited to ten per client address and two hundred overall per five minutes, at the sign-in form and for HTTP Basic.
- **More of the console follows the chosen language.** In English, the alert history errors, the export tooltips and the "could not reach the engine" message were Spanish, and the analyst always answered in Spanish with Spanish step labels. The analyst now answers and labels its steps in the console's language. The sign-in pages are still Spanish only.
- **The console's own API pins the Host on reads too.** `/api/console/me`, `/api/console/audit` and the accounts list did not check the Host header or, for two of them, a cross-site context. They share one guard with `/api/hub-token`.
