- **Long-lived parent processes no longer vanish from parent resolution.** The enricher forgot a process after 30 idle minutes, so on an ordinary IIS or SQL server `enrichment.parent_name` came back empty and the webshell, Office-spawns-shell and browser-spawns-shell rules went mute. A process now stays known until it terminates, its PID is reused or the per-host cap needs room (a parent that keeps spawning is the last to go); only a host silent for 24 h is retired.
- **"One account on three hosts in one hour" means one hour.** A user-scoped sequence added up the hosts an account touched without ever ageing them, so three hops spread over an afternoon fired a 1 h chain. Only hosts hit inside the window of the newest one count, and the alert lists just those.
- **Every suppression of a rule is evaluated, not only the first.** With two conditional entries for one rule the second was never tried, and a conditional entry hid a later unconditional one. The alert path now checks all the entries for the rule/host pair.
- **Converted Sigma rules honour Sigma escaping, `null` and unique ids.** `'\\\\host\\share'` was emitted with every backslash doubled and never matched, and `\*` became backslash plus wildcard; `Field: null` became the literal `<nil>`. Escapes are now processed (`\\` is one backslash, `\*` and `\?` are literal), `null` converts to "field empty" (or skips the rule under a modifier), and the branches of a split OR get distinct ids (`<uuid>-or1`, `-or2`…) instead of sharing one. Rules converted earlier should be regenerated; a pattern written `\*` meaning "backslash, anything" must be written `\\*`.
- **Active response protects system processes by path, not by name.** A binary named `lsass.exe` in any folder was reported `process_protected` and could not be killed. Protection now applies to csrss, smss, wininit, winlogon, services and lsass under `System32`, to the product's own binaries beside the engine, and to any process Windows marks critical; the check is repeated on the handle that performs the kill.
- **The process baseline cannot be talked into learning a tool silently.** A new name was learned even when its novelty was dropped by the 10-per-hour limit, so ten decoy names bought silence for the next one. A dropped novelty is no longer learned and is reported when budget returns, and a host with a full table (4096 names) keeps reporting unknown names instead of going quiet.
- **The LSASS memory-access rule tests the access bit instead of a list of masks.** It matched five exact masks; adding any unrelated right (`0x1438`, `0x1f3fff`, `0x1011`) evaded a critical rule. It now fires on every mask that includes `PROCESS_VM_READ`. Expect more alerts from tools that legitimately read LSASS; suppress those by rule and process.
- **`gt` and `lt` only compare numbers.** `lt 1024` matched every event that lacked the field, and non-numeric values fell back to alphabetical order. Both operators are now false unless both sides are numbers.
- **Rule files with a duplicate id, no id or name, or an unknown `event_type` fail to load.** A typo such as `process.created` loaded and never fired, and two rules sharing an id were indistinguishable in alerts and suppressions. The load now stops with the file and rule named (on hot reload the previous set stays active).
- **A late event can no longer reset a beacon detector, and duplicate timestamps do not blind it.** One sample older than the window wiped up to 64 samples and the cooldown mark; two connections with the same timestamp voided the regularity test for as long as they stayed in the ring. The stale sample is ignored while the destination is active and equal timestamps count once.
- **Beacons that sleep for minutes are detected.** The shipped profiles only saw cadences of up to about 80 s. A third profile, `bcn-periodic-slow` (medium), covers intervals from 75 s to about 34 minutes over a 4-hour window and tolerates implant-style jitter; with several profiles loaded, one profile holds at most half of a host's beacon keys. Fixed-timer software will match it: add those services to `exclude_domains`.
- **Evidence bundles survive a skewed endpoint clock, and the flight recorder is bounded in bytes.** The bundle window was measured from the engine's clock but filtered by the sensor's timestamps, so a skewed endpoint or an imported backlog produced a bundle holding only the trigger; the window is now anchored on the triggering event. The per-host ring is capped at 4 MiB as well as 256 events (it could reach about 16 GiB on a feed of oversized events).
- **The active-response cooldown treats `HOST`, `host` and ` host` as one machine.** The key used the literal host string while the host check ignored case and spaces.
- **A critical alert's webhook is no longer dropped behind a burst.** With 8 deliveries in flight the next one was discarded whatever its severity. Up to 64 deliveries now wait, the most severe go first, and when the queue is full the lowest severity is the one dropped (and counted in the log).
