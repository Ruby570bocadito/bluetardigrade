- **A file that cannot be read no longer holds process events or the sensor's shutdown.** The `process.create` event waited for its image hash on the single enrichment thread: one read the kernel never completed (an oplock, a hung filter driver) stalled every event queued behind it and the stop of the service. The read now runs on a helper the event waits for at most six seconds; while the helper is held, events go out without a hash (counted in `hash_dropped`) instead of queueing.
- **Registry, network and DNS events of short-lived processes keep their process name and user.** Those events arrive through another ETW session about a second after the process start and end, by which time the PID had been forgotten: a `reg.exe add ...\Run` produced a `registry.set` named `pid 1234` with no user. An exited process now stays in the table for 60 seconds; a start that reuses the PID replaces it.
- **The sensor service restarts after an error, and an engine that restarts during boot no longer leaves it stopped.** `sf-etw -Install` now sets the service's failure-actions flag (`sc.exe failureflag`): without it Windows only restarted the service after a crash, not after the error exit the sensor reports. A connection the engine cuts or leaves unanswered during the TLS or `AUTH` handshake is retried with backoff like an unreachable engine; a rejected token and a certificate that does not verify still stop the sensor with the reason in the log.
- **The heartbeat stops announcing telemetry the sensor has lost.** When the network/DNS/registry or the file ETW session ended on its own (stopped with `logman`, or failing), only a log line said so and the inventory kept showing `network+dns+registry`. Those streams now leave the capture label until the session is running again, the session is restarted with backoff, and the kernel session ending without a stop request ends the sensor with an error so the service manager restarts it.
- **Stopping the sensor saves its queue first.** Shutdown waited without limit for the memory sweep, up to 512 pending YARA scans and a TCP connect with no timeout before handing up to 50,000 queued events to the spool; `Stop-Service` killed the process before that. The queue now goes to the engine or the spool first, the sweep and the scanners stop between two regions or files, the connect has a five-second ceiling, and a worker that is still busy is left behind after two seconds.
- **The sensor does not send its token in clear to another machine.** Without `--tls-ca`, `AUTH <token>` and `ENROLL <token> <host>` crossed the network readable by anyone on the path. The sensor now refuses to send a token over a plain connection unless the engine is on the same machine, and `sf-etw -Install` refuses a remote `-Addr` without `-TlsCa` before changing anything. `--allow-plaintext-token` (sensor) and `-AllowPlaintextToken` (`sf-etw`) accept the risk explicitly, for a lab or a link protected below.
- **A file still held by its writer is scanned once it is released.** YARA scanning is triggered by the write, usually before the writer closes the file; the read failed with a sharing violation, and the file was remembered as scanned so it was never read again. Such a read is retried after 0.5, 2 and 8 seconds, and a file is remembered only after it was actually scanned.
- **`sf-etw -Install` passes `-TokenFile` and `-EnrollTokenFile` to its elevated step.** Run from a normal terminal, the relaunch forwarded `-Token` and `-EnrollToken` but silently dropped the file variants, installing a service without its token. Both travel now, with absolute paths, and a file that does not exist is reported before the UAC prompt.
- **The installers report the firewall rule truthfully.** A non-elevated `install.ps1 -Firewall` without a token said the existing rule was removed although `netsh` had failed; the manual command it printed omitted `profile=domain,private` and would have opened TCP 7777 on public networks; and a non-elevated uninstall left the inbound rule in place without a word. The outcome of each `netsh` call is checked, the printed command is the one the installer runs, and the uninstaller says when the rule is still there and how to remove it.
- **The sensor service keeps its data in `ProgramData\bluetardigrade-sensor`.** The old location, `ProgramData\bluetardigrade\sensor`, is also where a server install keeps the sensor's source crate: tokens, spool and log landed in the source tree and `sf-etw -Uninstall -Purge` deleted the sources. `sf-etw -Install` moves the data of an existing service to the new directory; a directory that is a source tree, or that is not restricted to SYSTEM and Administrators, is never touched.
- **Stopping or removing the sensor no longer leaves its ETW sessions running.** A sensor ended by `Stop-ScheduledTask` or by a service removal could not stop its own sessions, which stayed in the kernel until the next boot. `server.ps1 -Action Stop/Remove`, `sf-etw -Uninstall` and the uninstaller stop the three sessions by name, and the uninstallers wait for the service to stop before deleting it and say so when its files could not be removed.
- **The `sf-*` commands work from a profile with accented characters, and the uninstaller no longer rewrites the PATH through `reg.exe`.** The command shims embedded the install path in the ANSI code page while `cmd.exe` reads batch files in the console's code page, so an install under `C:\Users\José` could not start anything. The shims now locate the install from their own path (`%~dp0`) and are pure ASCII. The uninstaller edits the user PATH through the registry API, like the installer, instead of parsing `reg query` output that garbled such entries.
- **A damaged spool line no longer discards the rest of the spool, and the in-memory queue is bounded in bytes.** A line with invalid UTF-8 (a write torn by an abrupt stop) ended the replay and the remaining events were deleted with the file; it is now skipped and counted. The queue, limited only to 50,000 lines of up to 32K characters each, also stops at 64 MiB and overflows to the spool.
- **The Sysmon sensor recovers after its log is cleared, and never skips an event it failed to send.** After the Sysmon log was cleared or Sysmon reinstalled, the saved bookmark was above every new record and nothing was sent again while heartbeats continued; the bookmark is now dropped, with a warning, when it is past the end of the log. It also advanced before the event was written, so a failed send stored the id of an event that never left; it now moves only after the send.
- **The container's base images are pinned by digest.** `golang:1.27-alpine` and `alpine:3.24` were referenced by tag only, which can be moved to different content.
