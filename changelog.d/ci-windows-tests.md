- **The Windows CI job fails when `go test` fails.** Under `pwsh` a step only reports the exit code of its last native command, so a red `go test -count=1 ./...` followed by two green smokes passed: three tests asserting POSIX `0600` modes (which Windows cannot report), the known-software separator test and the store/database-query tests fail deterministically on Windows and had gone unseen. Each command now checks its own exit code, the mode assertions run where modes exist, and the kill-path tests that need `/proc` skip explicitly elsewhere (the Windows kill path keeps its real smoke). Developer tooling runs on Windows too: the YARA worker test compares against the JSON-escaped path, `notify_receiver.py` no longer calls the POSIX-only `signal.pause()`, `smoke_ingest_tls.sh` keeps Git Bash from rewriting the certificate subject, the E2E scripts pass paths to Python as arguments and derive the sequence and scenario counts from the shipped content (they still expected 11 sequences and 127 scenarios), the risk E2E compares two back-to-back reads of a decaying score, `e2e_respond_kill.sh` skips outside Linux pointing at `smoke_respond.ps1`, and every browser check honors `CONSOLE_CHROMIUM_PATH`.
