- **Domain sign-in in the console (AD-7, second half) and a redesigned sign-in page.** With `CONSOLE_DOMAIN_AUTH=1` and a users file, the sign-in page offers «Cuenta local» and «Cuenta del dominio» (a pair of radio buttons posted with the form: no script). A domain sign-in goes to the engine's `POST /api/auth/domain` server side, with the bridge token — it stays off the browser's write list, since no browser needs it and a pre-session route there would need a principal it cannot have — and the session opens like a local one under `DOMINIO\usuario`, a name no users-file account can carry: attributed and audited (`/login/dominio`), never mistaken for a local account of the same name by the password, two-step or attribution paths. The directory owns its password and second step, so those pages say so for a domain session; a role the users file asks a second step of (`mfa_required`) is refused for domain sign-in instead of opened with one factor; turning `CONSOLE_DOMAIN_AUTH` off ends every domain session. Each engine verdict gets its own message (bad credentials, no mapped group, throttled, engine without `-domain-auth`, DC unreachable, engine down) and the switch stays on «dominio» after a failure. On Windows, `tools\config\domain-auth.yaml` arms both halves: `sf-start` passes `-domain-auth` to the engine and turns the switch on in the console. The sign-in, second-step, recovery and password pages get a new look: a brand panel with the mark and what the console does (hidden on phones, where the mark sits above the card), a card with clearer fields, focus rings and an alert style, light and dark from the system setting, and the console icon as favicon. Still plain server-rendered HTML with no script. Tests: 8 new route tests (engine call and bearer, long UPNs, session name and source, every refusal audited, off means the engine is never asked, mfa_required refused, sessions end when turned off, switch only when on); console suite 613 tests, tsc, next build and the 9 sign-in browser checks green.
