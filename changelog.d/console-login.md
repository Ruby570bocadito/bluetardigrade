- **Console sign-in page and sessions.** With accounts (or the shared token), the browser gets a sign-in page at `/login` instead of its own Basic dialog, and a session cookie (HttpOnly, SameSite=Strict, Secure over HTTPS) that ends after 30 idle minutes, 12 hours, a sign-out from the session panel, or a change to the account's password or role. A page opened without a session comes back to where it was heading after signing in; an open console whose session ends returns to the sign-in page. Sign-ins and sign-outs are audited, and only the console's own page can submit them. Scripts keep using HTTP Basic. Behind HTTPS the console sends HSTS.
- **Accounts from the launcher.** `sf-console -AddUser <name> [-Role analyst|viewer]` creates an account or resets its password and role, and `sf-console -RemoveUser <name>` removes one; `sf-start` offers to create the administrator account while there is none. Elsewhere, `web/console/scripts/console-user.mjs --file <path>` edits the accounts file the same way.
