- **Two-step sign-in for console accounts.** An account can add a code from any authenticator app (TOTP, RFC 6238) from the session panel: the console shows a QR code, drawn on the server without a new dependency, and the key typed out, then hands over 10 single-use recovery codes, stored hashed. Signing in then takes the password and a code, or a recovery code. `sf-console -RequireMfa admin,analyst` makes it compulsory for those roles (an account without it sets it up right after its password), and `sf-console -ResetMfa <name>` removes it when a phone is lost. Five wrong codes in 15 minutes lock an account's second step; each code works once. Accounts with a second step cannot use HTTP Basic. `sf-engine doctor` validates the new fields and reports how many accounts have it.
- **Account tool fixes.** `console-user.mjs --file` now keeps every other field of the accounts file when it writes it, and compares account names without case, as the console does: adding `Ana` next to `ana` updates that account instead of writing a duplicate that locks the console.
