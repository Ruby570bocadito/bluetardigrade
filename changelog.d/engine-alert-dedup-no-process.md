- **Hits without a process identity no longer collapse into one alert per minute.** The alert dedup key was rule, host and process id, so every hit of a rule on a host from events that carry no process (pid 0) shared one key for the 60-second TTL: three registry run keys planted within a minute raised a single alert. Such hits now dedup by the event itself (rule, host, type and event id), as imported observations already did, so distinct events each raise and an exact replay of one stays silenced. From the 8 October audit (pull request #22). The shipped scenario library raises exactly the same 177 alerts in its 138 scenarios before and after, so no curated detection changes; the difference only shows when distinct process-less events hit the same rule on the same host within the TTL.
