- **Fixes from the 8 October audit that never reached main.** Pull request #22 carried them, but it fell 469 commits behind with every touched file rewritten (CRLF, spaces for tabs), so they are ported one by one onto the current code, each with a test that fails without it. The alert-latency p95 is the nearest-rank percentile (rounding 0.95n down read one rank too high whenever it was whole, and a 20-sample window reported its maximum). The live SSE broadcast skips the JSON marshal when no console is subscribed, work it paid for every ingested event. The ingest boundary strips the search field separator from attribute values too, which reach the haystacks through `ObservationSearchFields` (the fuzz invariant now covers them). `truncateRunes` returns a value whose bytes already fit without the `[]rune` copy, on the ingest hot path and in alert summaries. Two items were left out on purpose: rejecting `min_count: 2` in beacon profiles (the evaluation reads every sample in the window, so such a profile fires from the third connection on, and rejecting it would break configurations that work), and the fsync before renaming a forensic bundle, which costs about 60% more per bundle write on Windows and stays an operator decision while bundles are written synchronously on the alert path.
