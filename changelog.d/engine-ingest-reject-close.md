- **A rejected ingest client reads the reason on Windows too.** The engine closed a refused connection (an AUTH line against an engine without a token, a wrong token, an over-long line) with the client's data still unread, and closing a socket with unread input sends a RST instead of a FIN: on Windows the RST discards the error ack before the client reads it, or fails the client's next write, so a sender that pipelined events behind its AUTH line saw "connection forcibly closed" instead of the cause. The engine now shuts its write side after the ack and discards what the client already sent, for at most one second or 1 MiB, before closing. The bundled sensors wait for the AUTH ack, so their handshake was not affected; `TestTokenlessEngineRejectsAuthLine` failed intermittently on Windows because of it, and a new test reproduces the case every time without the fix.
