- **Engine and collector polish from the Windows test pass.** Windows PowerShell 5.1 puts a UTF-8 byte-order mark in front of what it pipes to a native program when the console code page is 65001, and Notepad or `Set-Content -Encoding UTF8` write one too: the ingest now drops it from the first line of a connection (it turned `AUTH <token>` into a refused handshake), and `engine secret-write`, the legacy raw secret files and the `--token-stdin` of `engine ingest-identity` and `engine operator-credential` drop it from the secret or token (an AD bind password or a stored token hash used to carry an invisible first character); UTF-16 secrets are refused with the fix. When the ingest port is held by a program that is not an engine, the engine now exits 1 naming it instead of exiting 0 with «stop it: sf-console -Stop» (another engine, detected through its API for up to 3 s while it starts, still gets the graceful exit), and a busy API port explains that the console cannot reach the engine while detection keeps running. The collector gains `-skip-invalid`: malformed records are skipped, reported by line number (never by content) and counted, and input with no valid record still fails; by default it still stops at the first one, and the error now names the option. `engine version` reports the newest released version of the changelog (`v1.0.0-rc1`, not `v1.0.0`; a test keeps the default and the changelog in step) and, for a build from a git checkout such as the installer's, the commit and whether it had local changes. The command list of `engine --help` sizes its column to the longest name, so `ingest-identity`, `operator-credential` and `secret-write` no longer run into their descriptions. The operations guide records the throughput measured on Windows 11.
