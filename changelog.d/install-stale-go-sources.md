- **Updating an old installation no longer breaks the engine build.** A Go file deleted upstream stayed behind in an updated install (git stops tracking it, and the zip overlay copies without removing), so the next `go build ./cmd/engine` failed with dozens of "redeclared in this block" errors: an install from 5 October kept the monolithic `internal/api/api.go` after it was split into `auth.go`, `alert_status.go`, `catalog.go` and others. `install.ps1` now moves such files aside as `<name>.go.stale-<date>` before building: on the git path, untracked `.go` files under `cmd`, `internal` and `pkg` that the history shows were deleted (a file never committed is someone's new work and stays); on the overlay path, `.go` files the downloaded tree no longer ships. Nothing is deleted, and each move is reported.
