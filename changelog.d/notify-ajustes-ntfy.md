- **Notifications edited from the console, ntfy push and the alert link (F3).** Administrators now manage the engine's notification channels in **Ajustes → Avisos externos**: add, edit and remove email, Telegram, Slack and the new **ntfy** channels, set each one's minimum severity and the console address, and save — the engine validates the list with the loader's own rules, commits `-notify` atomically (0600) and swaps the running channels in without a restart (`notify.Live`; the old ones drain their queues in the background). **Enviar prueba** sends a message plainly marked as a test to one channel or to all, synchronously, and shows each channel's own answer (never an endpoint or a credential). New engine API, gated like the AD settings (403 without `-api-write`, 501 without `-notify`, 409 when the file was edited by hand since startup): `GET`/`PUT /api/settings/notify` and `POST /api/notify/test`, documented in the OpenAPI contract. Secrets are write-only: a Slack hook URL, a Telegram or ntfy token and an SMTP password are never served back (`url_set` / `token_set` / `password_set`); an empty field keeps the stored value of the channel with the same name and type, `clear_secret` drops it, a renamed channel inherits nothing. The **ntfy** channel publishes JSON to a self-hostable server: `[SEVERITY] rule @ host` as the title, the severity as the priority (critical 5 rings through do-not-disturb), an optional bearer token (`token`/`token_env`). With the new top-level **`console_url`**, every Slack, Telegram and email message ends with the alert's link (`/?view=alertas&alert=<id>`) and an ntfy notification opens it on tap. `-notify` now accepts a file that does not exist yet (no channels until the console creates it) and an explicit `channels: []`; an existing broken file still stops the engine. `sf-start` always passes `-notify tools\config\notify.yaml`, `notify.example.yaml` gains `console_url` and an ntfy channel (a test loads the shipped example), and `sf-engine doctor` points at the console. The console proxy lets the two writes through for administrators only (32 KiB and 4 KiB caps). Tests: notify package (ntfy payload, priority and bearer, links, empty lists, optional file, console_url validation, round trip, test round, live swap), API (gates, secret-free GET, create-and-swap, secrets kept/cleared/not inherited, rejections and drift, per-channel test answers), proxy roles and caps, and the console client helpers; checked end to end against a real engine and a stand-in ntfy server.
