- **Notifications no longer die twice at shutdown.** A cancel landing while a notify channel's queue was busy could send half of the queued alerts into instant doomed attempts (each counted as failed) instead of the documented best-effort drain: the worker's select picked uniformly between the cancelled context and the queue. The worker now checks the context before every pop, so each queued frame gets exactly one drain attempt under a live context — bounded by the same 2s shutdown deadline — and only frames the deadline leaves behind are counted as dropped.
