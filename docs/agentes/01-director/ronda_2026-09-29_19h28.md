## Riesgos detectados

### Prioridad MEDIA
1. **[seguridad] Webhook de salida sin cabecera de autenticación** (global `-webhook` y por-regla `actions.webhook`): el POST no lleva `Authorization` configurable; un receptor SIEM serio la esperará, y en redes compartidas el token evita que un tercero reciba las alertas. Propuesta: flag/env `WEBHOOK_TOKEN` global + `config.secret` por acción (el paquete `actions` ya documenta "optionally with a Bearer secret" para el webhook por-regla — el global es el que falta). **Asignado a: Bugs/Seguridad.**
2. **[seguridad] Sin rotación de token de ingest:** el token es estático por proceso. Para despliegues duraderos, rotación sin downtime (dos tokens válidos en ventana) o al menos documentación del procedimiento manual. **Asignado a: Bugs/Seguridad (fase 2).**
3. **[packaging] Lockfiles duplicados en `web/console`** (`bun.lock` + `package-lock.json`): fuente de deriva; bun y npm no comparten resoluciones. Decidir uno (recomendación: solo `bun.lock`, es lo que usa el proyecto) o documentar por qué están ambos. **Asignado a: Implementaciones (decisión + limpieza).**
4. **[consola] `sf-console -Stop` no siempre encuentra el engine autostart** (detectado por Implementaciones 19h00): el autostart lanza el engine directo y el PID file existe (`run/*.pid`); barato de arreglar. **Asignado a: Implementaciones.**

### Prioridad BAJA
5. **[docs] PDF de arquitectura sin actualizar** (correlator, actions, export y auth no constan); Pulimiento ya lo tiene en cola — requiere host con las herramientas del PDF original.
6. **[detección] `image.load` sin cobertura en reglas** — en espera de hashes/firma en el schema (fase 2); el pack de 23 reglas sigue sin cubrir esa superficie.
7. **[reproducibilidad] `sensor/Cargo.lock` aún no versionado** (requiere host con Rust para generarlo); la nota en `.gitignore` ya describe el estado real.
