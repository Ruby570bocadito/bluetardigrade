## 5. Hallazgo vivo — ANSI en `internal/alert/alert.go` (asignado: 04)

Las siete constantes del bloque de color (líneas 27-36 del fichero actual) valen el byte 0x1b desnudo, sin parámetros SGR. Los usos (`alert.go:197-198` y `colorFor` en 257-265) concatenan estas constantes: `cBold + cMag` produce **dos bytes 0x1b consecutivos**, y la línea de alerta coloreada emite 0x1b seguido de texto imprimible — sin `[` no hay CSI, así que el terminal interpreta la basura como secuencias no estándar o la ignora: los colores de alertas por consola no funcionan y pueden dejar el terminal en estado raro. No es un problema de pipeline (el output JSON y la API no pasan por aquí) — es el camino `colored` del `Manager`.

Fix exacto que asigno a **04 (Bugs/Seguridad)** — es su dominio (bug catalogado en la ronda 1) y son 7 líneas:

```go
// ESC = byte 0x1b. En Go: "\x1b" (equivalente a backslash-033).
const (
    cReset = "\x1b[0m"
    cBold  = "\x1b[1m"
    cRed   = "\x1b[31m"
    cMag   = "\x1b[35m"
    cYel   = "\x1b[33m"
    cCyan  = "\x1b[36m"
    cGrey  = "\x1b[90m"
)
```

Verificación de cierre para 04: `gofmt -l` vacío tras editar (la trampa recurrente), y una comprobación visual de una alerta coloreada (o test del render a buffer con `colored: true` si lo prefiere mecanizable). El comentario del bloque de constantes ("disabled automatically when stdout is not a terminal") sigue siendo cierto y no necesita cambios.

Fuera de esto, **no encuentro defectos nuevos** en lo que he podido ejecutar y leer a fondo (`metrics.go`, `actions.go`, `lifecycle.go`, superficie del hub por sus 49 tests). `actions.go` merece mención positiva: cola acotada (8 en vuelo), techo de timeout (30 s), validación de scheme/host, drain del body, y el modelo de confianza SSRF documentado en el propio paquete tras la revisión de 04 — el nivel que el repo exige.
