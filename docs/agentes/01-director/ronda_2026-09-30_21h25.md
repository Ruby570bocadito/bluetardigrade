## 1. Arquitectura divergente y criterios de fusión

Las dos líneas habían resuelto el mismo problema de formas incompatibles; el criterio de cada decisión:

| Frente | Línea remota (8c81277) | Línea de rediseño (ba2e3df) | Decisión de fusión |
|---|---|---|---|
| Telemetría de consola | socket.io del hub para todo (eventos, alertas, stats, supresiones) | polling/SSE directo a la API del motor (`use-engine-stream`), socket solo para el analista IA | **Directa al motor** (más robusta, funciona sin hub); supresiones traídas por `/api/suppressions` directo |
| Stats type | `SimStats` con `interval_ms`/unión de modo | `EngineStats` verificado contra `internal/api` | Un tipo canónico `EngineStats` (superset con `suppressions_active` e `interval_ms?`), `SimStats` queda como alias |
| README | hero + TOC + features matrix + docs de auth/supresiones/CI | tablas verificadas (23 reglas, 4 secuencias), referencia CLI, config, comparativa | **Base remota + inserciones verificadas del Director** (644 líneas), TOC actualizado |
| Consola visual | React Bits sobre el diseño viejo (zinc viejo, glow, "tracer bullet") | rediseño completo (sidebar/topbar, zinc-950, Geist, severidades semánticas) | **Rediseño del Director + React Bits portado dentro** (BlurText en títulos, ShinyText en estado, AnimatedItem en telemetría) |
| CLI del motor | monolito con 5 flags nuevas (-api-token, -webhook-token, -token-previous, -suppressions, -pidfile) | refactor cobra/charm con subcomandos + TUI | **Refactor del Director con las 5 flags portadas** a `run.go` (13 flags runtime, compat de un guion intacta) |

Hub-side la división fue limpia: la línea remota nunca tocó `hub.ts` (el monolito `index.ts` era suyo), así que `index.ts` tomó la forma delgada del rediseño y el reenvío de supresiones se portó a `hub.ts` + `hub-state.ts` (snapshot con `suppressions`, limpieza honesta en `setDown`, `console:suppressions` solo cuando el payload cambia).

## 2. Hallazgos de la integración (defectos reales encontrados y corregidos)

1. **Contrato de `/api/suppressions` mal asumido en la consola**: el endpoint devuelve `{active, entries}` (objeto), no un array. El hook directo de la consola leía la respuesta como lista plana; corregido para desenvolver `entries` (alineado con `internal/api` `suppressPayload`). El bridge del hub sí lo leía bien.
2. **Tests con forma exacta del snapshot**: dos aserciones (`hub.test.ts`, `hub-state.test.ts`) fijaban las claves del snapshot sin `suppressions`; actualizadas a la forma nueva (aditiva).
3. **Corrupción de whitespace en la edición (trampa recurrente)**: `run.go` quedó con indentación de espacios tras las ediciones (cero tabs en el fichero); resuelto con `gofmt -w` al cerrar y verificado vacío en `gofmt -l`. Misma familia de trampa documentada en rondas anteriores: verificar por bytes, nunca por display.
4. **Driva factual residual en el README remoto**: `format=ndjson|csv` en la fila de export de alertas ya NO es deriva — el código actual acepta `jsonl`, `ndjson` (alias) y `csv` con test (`internal/api/export.go`); el fix factual de la ronda 3 del Director quedó obsoleto por evolución del código. El README fusionado mantiene la versión remota y la tabla CLI documenta los valores reales.

## 4. Smoke E2E real (binarios recién compilados, no mocks)

Escenario: motor con `-suppressions /tmp/suppressions.yaml -pidfile /tmp/sf-engine.pid` (puertos 17777/17778), hub en :13003 con `ENGINE_API` apuntando al motor, replay del `sf-devsensor` real.

1. **Arranque**: 23 reglas + 4 secuencias; banner de auth de loopback; **pidfile escrito** con el PID real y proceso verificado vivo.
2. **Supresión mal formada = fallo SONORO**: un YAML con formato incorrecto produjo `suppressions reload FAILED, keeping previous set` en cada tick — exactamente la semántica anti-silencio diseñada por 04.
3. **Supresión armada (formato lista, UUID completo, expiración)**: hot-reload la levantó en el siguiente tick (`suppressions reloaded (1 active)`), `GET /api/suppressions` la sirve con host normalizado a minúsculas, y en la segunda replay del devsensor la regla `5b7e1f38` (comsvcs) **no levantó alerta nueva** mientras `engine.log` registró `[SUPPRESS] rule=... host=LAB-WKS-01` exactamente una vez. La única alerta comsvcs en la API es anterior al armado (verificada por timestamp).
4. **Aprendizaje de la prueba**: la primera fixture de supresión usó el ID corto de la tabla README; la comparación es **exacta** contra el UUID completo y por eso no suprimió — comportamiento correcto del motor, fixture mal construida. La tabla de reglas del README muestra IDs de 8 hex por legibilidad; el operador debe copiar el `id` completo del YAML (queda como posible mejora menor de docs: columna de ID completo o nota).
5. **Cierre**: SIGTERM → `pidfile removed on shutdown (OK)`; pila limpia, cero procesos huérfanos.
6. **Hub**: `/health` en `ok` con contadores del motor fluyendo (eventos y alertas reales del replay).
