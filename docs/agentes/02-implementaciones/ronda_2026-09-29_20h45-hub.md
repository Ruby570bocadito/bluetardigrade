## Qué hace el hub (contexto)

El hub es el puente entre el API HTTP del motor Go (:7778) y la consola web: sincroniza el estado inicial (reglas, eventos, alertas), consume el stream SSE del motor, hace polling de stats cada 2s y republica todo por socket.io con el contrato exacto que la consola ya consume. Además sirve una superficie HTTP de operación (panel de estado `/`, `/health`, `/healthz`, 404/405) y aloja el analista de triage (LLM vía `ANALYST_BASE_URL`/`ANALYST_API_KEY`/`ANALYST_MODEL`, API compatible con OpenAI, sin ningún SDK privado).

## Bugs encontrados durante la verificación del Director (y arreglados)

El agente murió antes de ejecutar la suite; al verificarla el Director encontró **8 fallos** con tres causas raíz, documentadas porque son trampas de entorno reales:

1. **`Bun.serve` bufferiza los headers de un stream SSE hasta el primer byte y cierra requests idle a los 10 s** (`idleTimeout` por defecto). El motor fake del test no enviaba nada, así que el `fetch` del stream del bridge colgaba ~10 s, recibía `ECONNRESET`, y el re-establish en bucle retrasaba el attach >10 s (de ahí los timeouts de 5/8/10 s en cascada). FIX: el fake engine ahora envía `: ping` inicial y heartbeat cada 2 s (como un servidor SSE real), y `idleTimeout: 120` en ambos mocks. Además se añadió defensa de producción en `bridge.ts`: la fase de headers del stream tiene un presupuesto propio de 8 s (`Promise.race`, sin abortar el stream ya establecido).
2. **Test incompleto en cascada**: `analyst:ask without configuration` no emitía el evento `analyst:ask` antes del `waitEvent`, así que moría a los 5 s, la restauración de las env vars (línea posterior al fallo) nunca se ejecutaba y los dos tests siguientes corrían sin configuración. FIX: `socket.emit` añadido y restauración de env dentro de `try/finally`.
3. **Race honesto en el snapshot**: entre `onUp` y el primer poll de stats, el snapshot podía salir con `stats.mode = 'sin-motor'` aunque el motor ya estuviera conectado. FIX en `hub-state.ts`: el snapshot reporta el modo real (`engine`) con contadores a 0; sin números inventados.
4. **Shutdown colgado**: `io.close()` espera a todos los clientes; un cliente vivo retrasaba los afterAll (hooks "unnamed" con timeout). FIX en `hub.ts`: `io.disconnectSockets(true)` + guard de 2,5 s para un stop determinista.
