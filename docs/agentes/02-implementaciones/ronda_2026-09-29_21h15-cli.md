## Decisión técnica

El estándar de CLIs Go interactivas (Cobra + Charm) se adoptó tras la investigación del Director: `github.com/spf13/cobra` para subcomandos/ayuda, `github.com/charmbracelet/lipgloss` para estilos/tablas/colores y `github.com/charmbracelet/bubbletea` para el modo interactivo, más `golang.org/x/term` para detectar TTY. Los flags existentes de un guion (`-addr`, `-api`, `-rules`, ...) se preservan enganchando el `flag.FlagSet` nativo, porque `pflag` no soporta flags de un guion largos y la compatibilidad era un requisito duro.

## Contrato implementado (coincide con el README de la ronda 6-c)

- `engine run` con TODOS los flags anteriores + `-i`/`--interactive`.
- `engine rules [-rules dir]`: tabla lipgloss de las reglas cargadas (ID corto, nombre, severidad coloreada, tipo de evento, tags ATT&CK).
- `engine validate [-rules dir] [-sequences dir]`: reporte legible OK/avisos/errores con exit code correcto (0 OK, 1 errores); usa el nuevo `correlate.Manager.Snapshot()` para reportar referencias muertas de pasos de secuencia contra reglas cargadas (adición puramente aditiva: solo expone datos que el manager ya tenía, con sort estable).
- `engine version`: versión, runtime Go, OS/arch.
- Sin subcomando: comportamiento clásico intacto.
- `-h`: ayuda en español con uso, comandos y ejemplos.

## Modo interactivo

- Banner lipgloss al arrancar; si stdout no es TTY degrada a plano sin ANSI (mensaje explícito "running in plain mode") para no romper pipes ni logs.
- TUI bubbletea con stats en vivo, últimas alertas coloreadas por severidad, reglas cargadas y salida limpia con q/Ctrl+C (verificada la señal de apagado: shutdown limpio con métrica de eventos procesados).
- La lógica del motor no cambia: el modo interactivo es una capa de presentación sobre el `run` existente (ingest, rules, correlate, alert, api).
