## 2. Qué fija exactamente el test (9 tests, 58−29 = 29 expects)

`isTriageActionValid` (4 tests):

- **Vocabulario cerrado**: los tres estados (`new`/`acknowledged`/`closed`) pasan con campos opcionales ausentes — el enum completo, no un caso feliz.
- **Clases de id malformado, cada una por separado**: 15 chars (corto), no-hex (`g`), MAYÚSCULAS (el patrón es `[0-9a-f]`, no `i` flag — un id de otra fuente en mayúsculas NO pasa la puerta), vacío.
- **Estados fuera del vocabulario** con cast explícito: `triaged` y `''` → false.
- **Techos exactos**: nota 2000 pasa / 2001 falla; by 200 pasa / 201 falla — el borde inclusivo/exclusivo fijado en los cuatro puntos.

`postAlertStatus` (5 tests, stub de `globalThis.fetch` con captura de `(url, init)` — mismo patrón que `route.test.ts`, save/restore de `NEXT_PUBLIC_ENGINE_API`):

- **Fail-fast sin red**: acción inválida → ack con el mensaje canónico y **cero llamadas fetch** (el stub lanza si alguien toca la red — la aserción `calls.length === 0` no puede mentir).
- **Camino feliz**: URL exacta del proxy same-origin (`/api/engine/api/alerts/{id}/status`), método POST, cuerpo con los defaults aplicados (`note: ''`, `by: 'consola'` cuando ausentes), ack `ok: true` con la entry parseada.
- **Error del motor con cuerpo**: `{error: '...'}` con 429 → el mensaje del motor viaja verbatim al ack (es lo que la UI renderiza inline).
- **Error sin cuerpo parseable**: HTML 504 → fallback al status line (`el motor respondio 504`).
- **Fallo de red**: fetch que lanza → ack accionable, **nunca una excepción al caller** (`no se pudo registrar el estado: connection refused`).

## 3. Nota técnica para el siguiente (nuance de TS)

Un stub de fetch que solo lanza necesita anotación de retorno explícita `: Promise<Response>` para que el cast `as typeof fetch` componga: el retorno inferido de una función que siempre lanza es `Promise<never>`, y TS2352 lo declara "sin solapamiento suficiente" con `typeof fetch` (la propiedad `preconnect` del tipo dom lo fuerza). Los stubs que devuelven `Response` (el de `route.test.ts`, los míos) no lo necesitan. Documentado aquí para no quemar la pasada de tsc dos veces.
