  descripción genérica del SDK configurado, y documentado el env var
  `ENGINE_API` que faltaba).
- **Pendiente ineludible (para Implementaciones)**: el especificador de
  módulo `'z-ai-web-dev-sdk'` en el import y la dependencia
  `"z-ai-web-dev-sdk"` en `web/console-service/package.json` (y su

  del analista: es la implementación real del LLM. Sustituirla exige

  residual: 2 líneas de código + 1 línea de package.json.

### 2. Configuración del frontend saneada (web/console)

- **`tailwind.config.ts` eliminado (código muerto)**: el proyecto usa
  Tailwind v4 (`@import "tailwindcss"` + `@theme inline` en
  `globals.css`, plugin `@tailwindcss/postcss`). En v4 un fichero de
  configuración JS solo se aplica si se referencia con `@config`, y no
  hay ninguna referencia. Además el fichero seguía la convención v3
  (`hsl(var(--background))`, `darkMode: "class"`) incompatible con las
  variables oklch reales. Verificado antes de borrar: grep de `@config`
  en todo el paquete, sin coincidencias; build de producción posterior
  correcto.
- **Dependencia `tailwindcss-animate` eliminada** de
  `web/console/package.json` (+ regeneración de `bun.lock` con
  `bun install`): solo la importaba el config muerto. Las clases
  `animate-in`/`fade-*` que usa el código vienen de `tw-animate-css`
  (importado en `globals.css`), que se conserva. `bun.lock`
  actualizado coherentemente.
- **`@types/node` añadido** a devDependencies: `tsc --noEmit` fallaba
  con `TS2580: Cannot find name 'process'` en `socket-provider.tsx`
  (`process.env.NEXT_PUBLIC_CONSOLE_URL`). Era el único error de tipos
  del paquete.
- **`next.config.ts`**: eliminado `typescript.ignoreBuildErrors: true`
  (ocultaba errores de tipos al compilar, mala práctica en un repo de
  producción; tras añadir `@types/node`, `tsc --noEmit` pasa limpio y
  `next build` ejecuta su fase de TypeScript correctamente);
  `reactStrictMode` cambiado a `true` (recomendado en Next; verificado
  que el efecto del socket en `socket-provider.tsx` tiene cleanup
  correcto, así que el doble montaje en dev es seguro); eliminado el
  comentario de scaffolding `/* config options here */`.
- **Impacto**: el build vuelve a validar tipos de verdad, el CSS real
  no dependía del config borrado, y las dependencias declaradas
  reflejan solo lo usado.

### 3. Packaging

- **Dockerfile**: la imagen copiaba `rules/` pero no `sequences/`, así
  que el correlador de kill-chains (ya cargado por el binario cuando el
  directorio existe) quedaba silenciosamente desactivado en contenedor.
  Se añade `COPY sequences/` y el flag `-sequences` al CMD. Sin riesgo:
  `correlate.LoadDir` solo se invoca si el directorio existe.
- **install.ps1**: la cabecera ("What it does", punto 5) no mencionaba
  `sf-sensor` en la lista de shims instalados, aunque `Write-Shims` lo
  instala desde el commit de telemetría real. Documentación interna del
  script sincronizada con lo que hace el código.
- **.gitignore**: (a) dejado de ignorar `sensor/Cargo.lock` — para un
  crate binario la convención Rust es versionar el lock (builds
  reproducibles); el primer build en Windows debe añadir el fichero,
  queda nota en el propio .gitignore y en este informe. (b) Añadida
  protección de `.env` / `.env.*` (con excepción `!.env.example`) para
  que credenciales locales de la consola no entren nunca al repo.

## Bugs o problemas de seguridad detectados (para Bugs/Seguridad)

1. **Bug funcional — hot-reload del motor con ruta no resuelta
   (prioridad ALTA)**: en `cmd/engine/main.go`, la recarga periódica
   llama a `engine.Reload(*rulesDir)` usando el valor crudo del flag
   `-rules`. Cuando el directorio de reglas se resolvió por el fallback
   relativo al ejecutable (instalación `sf-engine`, sin `-rules`
   explícito y sin `./rules` en el CWD), la recarga apunta a una ruta
   que no existe y `Reload` falla silenciosamente (el error se descarta
   con `err == nil`): el motor seguiría evaluando el pack antiguo
   aunque el usuario edite las reglas. La recarga de secuencias sí usa
   la ruta resuelta (`seqPath`), por lo que el fix probable sea
   simétrico (usar `rulesPath`), pero se deja intacto a propósito para
   el agente correspondiente.
2. **Nota (media)**: `web/console-service/index.ts` declara
   `cors: { origin: '*' }` en socket.io y la API del motor escucha en
   todas las interfaces (`:7778`) sin CORS restrictivo. En un despliegue
   local/LAB es aceptable, pero conviene revisarlo si el hub se expone
   en red (el README ya sugiere `:7777` abierto con `-Firewall`).
3. **Nota (baja)**: el package `z-ai-web-dev-sdk` (ver punto 1) ejecuta
   código de terceros con credenciales del entorno; evaluar su
   sustitución por un cliente mínimo propio reduce superficie de
   suministro.
