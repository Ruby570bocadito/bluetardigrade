## Cambios (qué se pulió, por qué, ficheros, impacto)

### POL-A-docs-1 — `docs/ARCHITECTURE.md` layout

- **Qué:** el bloque «Repository layout» (líneas 74-124) listaba 21
  paquetes `internal/`. Faltaban 8 con código y tests vivos:
  `baseline`, `fleet`, `forensic`, `incident`, `intel`, `reputation`,
  `tlsutil`, `yamlcheck`.
- **Por qué:** deriva factual real. Un lector del layout no se
  enteraba de que existen el grabador de evidencias forenses
  (`internal/forensic/`), el rotador de TLS (`internal/tlsutil/`), el
  emparejador de inteligencia offline (`internal/intel/`), las
  consultas a VirusTotal/AbuseIPDB (`internal/reputation/`), el
  inventario de flota (`internal/fleet/`), la línea base por host
  (`internal/baseline/`), los casos de investigación
  (`internal/incident/`) ni el guard anti-bomba YAML
  (`internal/yamlcheck/`). Cada uno está referenciado desde `api.go` o
  `run.go`, así que el layout los omitía sin razón.
- **Ficheros:** `docs/ARCHITECTURE.md` (+8 líneas, una por paquete).
- **Impacto:** el layout ahora cuadra 1:1 con `ls internal/` (29
  paquetes). Verificado con `sed -n '74,124p'` + comparación manual.

### POL-A-docs-3 — `docs/OPERATIONS.md` campaigns

- **Qué:** la sección «Kill-chain correlation» (alrededor de la línea
  933) documentaba `sequences/kill-chains.yaml` (4 secuencias, con

  `sequences/campaigns.yaml` (7 secuencias añadidas en el commit

### POL-A-docs-2 — `.gitignore` cobertura

- **Qué:** añadidas entradas para `coverage.txt`, `coverage.html`,
  `*.cover`, `*.prof`, `*.pprof` con un comentario explicativo.
- **Por qué:** higiene preventiva. El repo es Go-heavy y `go test
  -coverprofile` / `-cpuprofile` / `-memprofile` generan estos
  ficheros; sin ignore, un `git add .` descuidado los puede staged.
  Verificado con `find` que NINGÚN fichero real del árbol matches
  estos patrones hoy, así que la adición es segura.
- **Ficheros:** `.gitignore` (+7 líneas).
- **Impacto:** `git check-ignore coverage.txt coverage.html test.cover
  cpu.prof mem.pprof` ahora los atrapa; los ficheros tracked
  (`docs/ARCHITECTURE.md`, `internal/api/api.go`, etc.) siguen sin
  estar ignorados (verificado).
