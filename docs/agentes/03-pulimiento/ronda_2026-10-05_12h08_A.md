## Cambios (qué se pulió, por qué, ficheros, impacto)

### POL-A-docs-4 + POL-A-docs-5 — tablas de flags completas

- **Qué:** `docs/OPERATIONS.md` tiene dos tablas de flags del motor:
  1. **Configuration reference** (línea ~147), que dice «This is the
     full surface — there are no other knobs».
  2. **`engine run` flags** (línea ~1078), la referencia de CLI.
  Ambas estaban incompletas y la afirmación «full surface» era falsa.
  Comparé las tablas contra `cmd/engine/flags.go` (40 entradas) y
  añadí las que faltaban:

  | Flag | ¿Dónde faltaba? | ¿Por qué importa? |
  |---|---|---|
  | `-intel` | config reference | directorio de listas de inteligencia offline; sin esto el operador no sabe que existe |
  | `-baseline-learn` | config reference | ventana de aprendizaje de la línea base por host |
  | `-thresholds` | config reference | fichero del detector volumétrico (A2) |
  | `-notify` | ambas tablas | config de canales externos (Slack/Telegram/email); solo estaba en prosa, no en ninguna tabla |
  | `-api-cert` / `-api-key` | **ambas tablas y toda la doc** | TLS del API listener; `internal/api/api.go` `NewTLS` + `tlsutil.Reloader` lo soportan, pero NINGÚN sitio decía cómo activarlo |
  | `-ingest-cert` / `-ingest-key` | CLI reference | TLS del ingest listener; estaba en la config reference pero no en la CLI reference |
  | `-lifecycle` | CLI reference | fichero de triaje de alertas; estaba en la config reference pero no en la CLI reference |
  | `-incidents` | **ambas tablas** | fichero de casos de investigación; solo mencionado en prosa en la sección «Incidents» |

- **Por qué:** deriva factual real. Un operador que despliega el API
  más allá de loopback y quiere cifrarlo no encuentra cómo en la
  documentación, aunque el código lo soporta desde hace tiempo. La
  afirmación «full surface — no other knobs» es hoy cierta.
- **Ficheros:** `docs/OPERATIONS.md` (+8 filas en config reference,
  +7 filas en CLI reference).
- **Impacto:** ambas tablas ahora listan las 40 entradas de
  `flags.go`. Verificado con `sed -n` + `grep -oP '^\| `-\S+'` +
  comparación manual contra `flags.go`.

### POL-A-docs-6 — sección «Local HTTP API»

- **Qué:** añadido un párrafo tras el existente sobre `-api-token`
  que documenta `-api-cert`/`-api-key`: par PEM (both or neither),
  listener envuelto en TLS, hot-rotated on file mtime change, mismo
  patrón que `-ingest-cert`/`-ingest-key`, fail-loud en arranque si
  el par no carga, línea de despliegue típica
  (`sf-engine -api 0.0.0.0:7778 -api-cert c.pem -api-key k.pem -api-token ...`)
  y la advertencia de reverse proxy (si la terminación TLS ocurre
  en otro sitio, el bearer viaja en claro).
- **Por qué:** la sección documentaba el bearer pero no el cifrado.
  `-api-cert`/`-api-key` son críticos para despliegues no-loopback.
- **Ficheros:** `docs/OPERATIONS.md` (+1 párrafo).
- **Impacto:** un operador que lea la sección «Local HTTP API»
  encuentra ahora el camino completo (auth + cifrado) sin tener que
  ir al código Go.
