## 4. Defecto propuesto #34 (media) — `internal/actions/actions.go:209`: rama NewRequest sin redactar

El fix 05b2ab6 cubrió la rama de **transporte** (Do → :224 con `redactedURLErr`) pero la rama de **build** quedó cruda:

```go
req, err := http.NewRequest(http.MethodPost, rawURL, bytes.NewReader(payload))
if err != nil {
        d.log.Printf("webhook %s: %v", name, err)   // :209 — *url.Error Op:parse ECOA la URL completa
```

`url.Error.Error()` incluye la URL cruda (`parse "https://collector.example/hooks/SECRETTOKEN?x=%zz": invalid URL escape "%zz"`). Una URL de acción malformada **con credencial en path/query** (regla de la casa: el hook es la credencial) se imprime en el log **en cada entrega** de esa acción (deliver es por-alerta, :199) — sistemático una vez malconfigurado. Los otros tres paquetes cubren esta rama (webhook en el punto de log, notify en creación, siem en el punto de log): este es el único sitio descubierto del árbol.

**Parche (1 token, el helper ya existe a 6 líneas):**

```diff
-        d.log.Printf("webhook %s: %v", name, err)
+        d.log.Printf("webhook %s: %v", name, redactedURLErr(err))
```

**Falsabilidad:** test en `actions_test.go`: dispatcher con URL `https://collector.example/hooks/SECRETTOKEN?x=%zz` (parse error real) → pre-fix: `SECRETTOKEN` presente en el log capturado; post-fix: ausente, presente `destino: invalid URL escape`. Comportamiento invariante (retorno temprano, sin reintento, contador sin cambio: el fallo es de construcción, no de entrega).
