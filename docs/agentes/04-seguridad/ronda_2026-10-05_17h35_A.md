## SEG-B (rama `carril/seguridad-b`): sin bug funcional que corregir

- **`internal/scenrun/scenrun.go` (run-id bajo fallback de entropía)**: el
  fallback pasa de `run-%d` (19 dígitos decimales, que `GET
  /api/scenarios/runs/{id}` rechazaría) a `fallbackRunID` con
  `run-%016x` — un int64 no negativo son siempre 16 dígitos hex
  minúsculas, así que la forma del wire (`^run-[0-9a-f]{16}$`) se
  conserva y el run sigue consultable con la entropía rota. El guardia
  del contrato se centraliza en `scenrun.ValidRunID` (antes el patrón
  vivía duplicado en `internal/api/scenarios.go`). Test nuevo
  (`TestRunIDsMatchWireContract`) que cubre el mint criptográfico, cinco
  estampas del fallback y siete formas malformadas. Correcto.
- **`internal/api/security_headers.go` (nuevo)**: `nosniff` +
  `no-referrer` como wrapper MÁS EXTERNO del Hub (`api.go:230`,
  fuera de rebinding/auth/origin), así que cubre también 401/403.
  `Cache-Control` deliberadamente no forzado (SSE y descargas fijan el
  suyo por ruta): decisión correcta y documentada en el propio fichero.
  La ingesta (7778, protocolo propio) no lo necesita.
- **`scripts/dev-tests/check_openapi.py`**: la regex del fixture admite
  el nuevo envoltorio y el self-test suma un positivo con
  `securityHeaders(...)` — coherente con el cableado real.
- **`web/console-service/analyst.ts`**: `cleanAlertObject` blinda el
  fallback de alerta única (campos conocidos, cadenas recortadas,
  arrays filtrados y acotados). Detalle revisado y descartado como bug:
  `rule_id` no se acota en longitud, pero el constructor del prompt acota
  CADA bloque JSON (`clampBlock`: 4096/1024/2048/2000), así que un
  `rule_id` gigante no puede inflar el prompt; en las notas ATT&CK solo
  se usa para igualar contra `rule.id` cargado (no coincide, no se pinta).
  `hub.ts` usa el mismo saneado para la copia del socket. Bien.
