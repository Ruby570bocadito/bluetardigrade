## Correcciones

### 1. El fichero del registro del alta cargaba con digests de token duplicados — **severidad: baja** (requiere fichero manipulado o corrupto, pero rompe el contrato de confianza del arranque)

- **Descripción:** `Open` (`internal/enroll/enroll.go`) valida que cada
  registro tenga digest bien formado, que los **ids** de token sean únicos,
  que los **nombres** de identidad sean únicos y que los **digests de host**
  sean únicos (vía `byDigest`) — pero **no** que los digests de los tokens
  no se repitan. Un `hosts.json` con dos registros de token compartiendo
  digest cargaba sin error. Como `findTokenLocked` resuelve el token por
  digest con «gana el último», la credencial correspondiente apuntaba a uno
  u otro registro según el orden del fichero: un revocado en la consola
  podía dejar el sensor autenticando contra el otro registro — la UI
  muestra el token muerto y el sensor sigue entregando eventos. Hallazgo ya
  anotado como menor en la ronda 1; este arreglo lo cierra.
- **Causa raíz:** la validación de duplicados de `Open` cubría ids de token
  y nombres/digests de host, pero no los digests de token, y el mapa
  `byDigest` silenció la ambigüedad en el lado de host.
- **Solución:** la pasada de tokens de `Open` lleva ahora un mapa de
  digests y rechaza el fichero con el mismo error de siempre («token #%d is
  malformed or duplicated»), igual que los ids duplicados. La ruta de
  escritura no puede crear duplicados (`randomSecret`), así que el cambio
  solo endurece la carga de ficheros manipulados.
- **Test:** `TestOpenRefusesDuplicateTokenDigests`
  (`internal/enroll/fuzz_test.go`) — falla antes del arreglo («Open accepted
  a file where two tokens share one digest»), pasa después.
- **Cómo verificarlo:** `go test ./internal/enroll/ -run
  TestOpenRefusesDuplicateTokenDigests -v`.

## Fuzzing (SEC-7): `FuzzOpenRegistry`

Nuevo target en `internal/enroll/fuzz_test.go` contra el fichero que el
motor confía en cada arranque. Propiedades: `Open` nunca entra en pánico
con bytes arbitrarios; o falla con voz o devuelve un registro
autoconsistente (ids de token únicos, digests de token y host únicos y bien
formados, nombres únicos, estados del conjunto cerrado, `Counts()` en
cuadre); y lo aceptado sobrevive a un ciclo de escritura real
(`CreateToken` guarda; el fichero salvado reabre limpio). Semillas: fichero
vacío válido, un fichero real generado por el escritor (con token y alta),
versión equivocada, JSON truncado y tipos erróneos.

Sesión: 60 s, 3.469 ejecuciones (lento por E/S de fichero real por
iteración: escritura, apertura, alta de token y guardado atómico
temp+rename). **Ningún contraejema tras el arreglo**; el corpus del
descubrimiento nocturno de PUL-A lo hereda automáticamente.
